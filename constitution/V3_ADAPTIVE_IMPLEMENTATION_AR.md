# تطوير خوارزمية المساقط V3 — تكامل هندسي تجريبي

**حالة النطاق:** توليد مسودات قابلة للمراجعة، وليس مخططات اعتماد أو إصدار تنفيذ.

## ما تغير فعليًا
1. `backend/design/adaptive_geometry.py`: خوارزمية تكوين **أجنحة بارتدادات مستقلة ومتغيرة** على جانبي موزع متصل. تتغير حدود المبنى حسب نسبة موضع الموزع والتقسيم ومقادير التراجع، مع الاشتقاق النهائي للحدود من الخلايا المشغولة. ليست قوالب L/U/متدرج مقررة مسبقًا.
2. `backend/design/general_engine.py`: عائلة بحث `adaptive`، واستراتيجية تخصيص `relationship_aware` تعطي وزناً حقيقياً لتقارب المطبخ والطعام والمعيشة والحمامات وغرف النوم، ولفصل منطقة الضيوف.
3. `backend/design/functional_intelligence.py`: قياس مستقل لمسارات الأبواب والعلاقات الأساسية وكشف انقطاع الاتصال والتفاف الحركة وانكشاف حيز الأسرة ضمن حدود البيانات الممثلة.
4. `backend/design/architect_planner.py`: مسار توليد تجريبي **مفصول عن السلوك الافتراضي السابق**؛ يبحث في adaptive/spine/cross فقط، ويعيد البحث باستخدام استراتيجيات جديدة عند نقص البدائل السليمة أو ضعف مؤشر العلاقات. يحتفظ بأسباب الإصلاح وخياراته في `planning.generation_v3.automatic_repair`. لا يحذف الغرف ولا يرخّي قواعد القبول.
5. `backend/design/design_selection.py`: صار مؤشر العلاقات المَقيسة يدخل في ترتيب البدائل في وضع V3 فقط، بعد اجتياز الفحوص الهندسية الصارمة.
6. إصدار المتصفح المبني باستخدام `lovable_integration/build.py` يستخدم V3 مع طبقة تدقيق الدستور V2، ويعرض أسباب المقارنة وجولات الإصلاح، بشرط أن يُعاد بناء الموقع ونشره فعليًا.

## API
- الوضع القديم دون تغيير: `POST /api/v3/auto-design`.
- تجربة المحرك الجديد: `POST /api/v3/auto-design?generation_v3=true&constitution_v2=true`.
- API / Pyodide يشتركان في خوارزميات توليد Python ذاتها.

## ضمانات وحدود
- يرفض البحث المقترحات التي تفشل في الفحوص الهندسية المحسوبة فعليًا؛ وأي بديل غير كافٍ يُبلَّغ عنه صراحة بدل إكمال ثلاثة بدائل صورية.
- تشكيل الكتلة **حر نسبياً ضمن بحث هندسي متعامد وأجنحة متصلة**، وليس حلًا شاملاً لكل مضلع أرض أو شكل معماري محتمل. ما زال يدعم قطعة مستطيلة، دورًا أو دورين، وملحقًا اختياريًا ضمن القيود السابقة.
- لا يتضمن دراسة إنشائية/صوتية/محاكاة ضوء نهاري وتهوية أو خلوصات صيانة وتخارج معتمدة، ولا إذن فتح النوافذ أو تصديق اشتراطات البلدية؛ هي بنود REVIEW/PENDING.
- اختبار DXF 2010 يثبت سلامة الملف وإعادة قراءته بواسطة `ezdxf`، لا الاعتماد الهندسي أو فحصه داخل AutoCAD فعلي.
- لا يغيّر اعتماد المساقط السابقة أو وثائق القواعد الرسمية، ولا ينشر نفسه تلقائيًا على استضافة `chatgpt.site`.

## الفحوص
`pytest -q tests/test_adaptive_functional_v3.py`، ثم `pytest -q`، وفحوص JavaScript والواجهة. يجب التحقق يدويًا من مخرجات ثلاث حالات مختلفة ومعاينة مقارنة الأبواب والمداخل والنوافذ والأثاث والحركة والنسب المعمارية قبل وصفها باحترافية تنفيذية.

## التطوير المتبقي للهدف النهائي
- تحسين التكوين إلى مضلعات غير متعامدة، وأراضٍ متعددة الأضلاع ومستويات معقدة، عبر محلل قيود عام وطرق بحث أو تحسين رياضي.
- إصلاح موضعي واعٍ بالغرف/الأبواب، وليس فقط إعادة البحث عن توزيع آخر.
- نموذج رؤية للخصوصية والحجب الصوتي وحسابات إنارة وتهوية وخدمات وإخلاء.
- قيود تصميم إنشائي وإنهاء تفاصيل التنفيذ وجداول الأبعاد مع مراجعة واعتماد مختص.
