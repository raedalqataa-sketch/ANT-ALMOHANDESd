# نواة المحرك المركزي

المسار الجديد يستخدم برنامج العميل والأرض ومحرك توليد V4 في المستودع، مع طبقة إصدار مستقلة. يتولى المحرك اقتراح الفراغات، والبحث في الكتل والعلاقات، وفحص مسارات الحركة والأثاث، وإعادة التخطيط والإصلاح القابل للتراجع. تعيد بوابة التصدير التحقق من بصمة الهندسة وفحوص V4. تتحقق طبقة الإصدار من اكتمال ملفات المسقط وتبصم محتوى كل ملف. يتيح رابط الملف تنزيله من تشغيله وحده ما دام محتواه يطابق البصمة.

## ما اعتمدناه من الفروع

| مجموعة الفروع | القرار في النواة |
| --- | --- |
| الكتل وتنوع التوزيع والمسارات الوظيفية | استخدام البحث المتكيف وتصفية البدائل المتشابهة من مسار V4 المتحقق منه. |
| فروع الأبواب والفرش وإعادة التخطيط | تفعيل فحوص V4 لمسارات الأبواب والفرش، والتدقيق الهندسي المستقل، والإصلاح المحلي قبل قبول الرسم. لا ينتقل التخطيط الثابت لأحد الفروع إلى طلب جديد. |
| كفاءة المساحات والنقد المعماري | قياس اتحاد مساحات الحركة ومناطق الهدر الهندسية بعد التوليد، وحفظ القياسات مع البديل. يبقى ترتيب المحرك المتوافق مع أولوية العميل كما هو. |
| الفرع العلاقي 012/013 | تطبيق فكرة الخلوص أمام النافذة على الفتحات الفعلية كناتج تشخيصي. يعرض مناطق العوائق المرسومة فقط. صنّف الاختبار العميق فرع البحث العلاقي مرشحًا لمزيد من التحقق قبل ربطه بالإصدار. |
| فروع البلدية والأرض | استخدام بيانات الموقع ومقترحات الارتدادات المتاحة من المسار الأساسي. تظهر البنود التي تحتاج مستندات أو مراجعة محلية في النتائج. |
| واجهة العميل وإدارة عامل المتصفح | أساس الفرع الحالي يتضمن تجربة العميل المتحققة سابقًا. يوفر هذا العمل واجهة HTTP مستقلة للتكامل اللاحق، ويستمر تشغيل الواجهة السابقة بعقدها الحالي. |
| مزوّدو الذكاء اللغوي والتقارير التشغيلية | يبقون خارج مسار الحساب الهندسي. تعمل النواة محليًا دون حساب مدفوع أو مفتاح خدمة. |

لم نشغّل كل حزم الاختبارات الطويلة على كل فرع. سجّلنا بصمة كل فرع من الفروع الـ51 التي كانت على GitHub وقت التدقيق، بما فيها فرع واجهة العميل. نجحت ترجمة Python والفحوص الأساسية المختارة لكل فرع بعد إعادة تشغيل حالتين. كانت إعادة التشغيل بسبب تبعية SciPy الناقصة في بيئة الفحص، ومهلة قصيرة لاختبار إعادة توزيع المجموعات الوظيفية. في الاختبار الأعمق للفرع العلاقي نجح 30 اختبارًا وأخفق اختبار واحد. أعطى فحص المرحلة 010 نتيجة قبول هندسي حيث كانت العينة تتوقع الرفض وإعادة التخطيط بسبب ممر طويل. يمكن مراجعة الأوامر والنتائج في `branch_audit.json`.

## اختبار المحرك بوصفه مسارًا كاملًا

تستخدم المقارنة البرامج نفسها في V3 مع الدستور V2 وفي المسار المركزي V4. تمثل الأرقام هنا البديل الأول في ترتيب كل مسار.

| الطلب | بدائل V3 / المركزية | أكبر مسطح دور في V3 / المركزية | اتحاد مساحات الحركة في V3 / المركزية |
| --- | ---: | ---: | ---: |
| فيلا متوسطة في الرياض | 3 / 3 | 232.18 / 163.04 م² | 75.67 / 58.85 م² |
| فيلا فاخرة بدورين في الرياض | 3 / 3 | 264.28 / 180.18 م² | 78.27 / 77.49 م² |
| منزل بمجلس مستقل في صنعاء | 3 / 3 | 205.20 / 165.12 م² | 68.75 / 61.89 م² |
| أرض 8 × 8 م وأسرة من 12 شخصًا في دور واحد | 0 / 0 | تعذّر بعد الارتدادات | لا رسم |

حافظت الحلول المقبولة على الفراغات المطلوبة حسب فحوص البرنامج. تشير المساحات إلى أن البدائل الأولى أكثر إحكامًا في هذه العينة. يبقى تقييم راحة الفراغات وجودة التكوين للمراجعة المعمارية. استغرق المسار المركزي وقت بحث أطول من V3. تظهر نتائج كل بديل والزمن في `benchmark_results.json`. نجحت 15 حالة اختبار للعقد والواجهة والحساب الهندسي. تولّد اختبار HTTP الحقيقي ثلاثة بدائل، وقرأ PDF وDXF من روابطها، وتأكد من رفض الطلب الضيق وإخفاء ملفات غير صادرة.

## التشغيل

يتطلب تشغيل المحرك اعتماديات `requirements.txt`. يستخدم اختبار الفروع SciPy لفحص فرع MILP فقط.

```sh
git fetch --depth=1 origin '+refs/heads/*:refs/remotes/origin/*'
git ls-remote --heads origin > /tmp/ant-branches.txt
python -m quality_review.central_engine.audit_branches --refs /tmp/ant-branches.txt --output /tmp/ant-branches.json --timeout 240
python -m quality_review.central_engine.benchmark --out /tmp/ant-engine-benchmark
python -m pytest -q tests/test_central_engine.py tests/test_api.py tests/test_engineering_integration_v4.py
uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

أرسل أحد برامج `briefs.json` إلى `POST /api/central/v1/design`. يحتوي الرد على حالة الطلب وعدد البدائل والقياسات وروابط الملفات. تكتب مخرجات التشغيل في `outputs/central`. تشغيل هذا المسار من واجهة العميل الجديدة وإعداده للحفظ والسياسات والمشاركة على موقع إنتاجي مراحل مستقلة.

## ما يحتاجه الجيل التالي

- اختبارات عمياء تكفي لتقييم التكوين المعماري وتدرّج الخصوصية وعلاقة المسقط بموقعه.
- تعميم حل العلاقات المتزامن خارج العينة الثابتة. استكمال بوابات الأبواب والفرش ومسارات الحركة قبل إشراكه في الإصدار العام.
- دعم الأراضي غير المستطيلة والكتل المنحنية والسلالم المفتوحة في المسار المرتبط بالأرض. يتطلب ذلك مرشح توليد صالحًا وتمثيل هندسة وفحوص تصدير متطابقة.
- التحقق المحلي الشامل والإنشائي والميكانيكي مسؤوليات تحتاج أدلة ومدخلات إضافية قبل عرض اعتماد تنفيذي.
