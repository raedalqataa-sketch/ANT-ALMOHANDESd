# مراجعة الإضافات المعمارية 0.6

المهمة: ربط توسعات الاشتراطات البلدية بواجهة العميل، وإنشاء العناصر المطلوبة داخل المساقط، ثم نشرها في الموقع الحالي مع إبقاء دراسة المحفد.

المنفذ: خيارات مستقلة للمنور والملحق والشرفة وساحة الخدمات. تُحجز المساحات في البحث؛ تُنشأ الغرف والجدران والأبواب والنوافذ والأثاث في الملحق، وتربط بئر درج متطابقة ووصولًا لا يسمح بالمشي فوق فراغ البئر. المنور فراغ مفتوح مع نوافذ فعلية وباب صيانة. الشرفة بلاطة ودرابزين مقترح وباب زجاجي منزلق، وليست مضلع مراجعة فقط. ساحة الخدمات تتضمن مواضع أجهزة أرضية خارج الغرف والمواقف ومسار المدخل.

التحقق: اختبارات البرنامج والهندسة والحركة، اختبار كل خيار منفردًا، واجتماع الخيارات الأربعة على حالة 24×32م، وإتلاف متعمد للملحق أو حذف ساحة الخدمات لإثبات الفشل. حالة 20×30م بكامل الإضافات تُظهر التعذر ولا تحذف الغرف لتزييف النجاح. يبقى البحث محدودًا؛ لا يثبت التعذر الحسابي استحالة الحل معماريًا.

فحص Chromium يغطي الواجهة العربية، خيارات الموقع، توليد L وU قابلين للمراجعة بالإضافات الأربع، تبويبات GF وFF وRF وSITE، التنزيل الفعلي، استعادة الاختيار، تعطيل الروابط عند تغيير المتطلبات، واجهة 390px، واستيراد وحفظ وإرسال regulatory_geometry للمحرك دون إسقاطه. لا توجد طلبات تشغيل خارج الموقع أو أخطاء JavaScript في حالة الفحص.

PDF يشمل الأدوار والملحق والموقع وتقرير المراجعة (5 صفحات في حالة الدورين والملحق). يُعاد فتح ملف DXF المنزّل لفحص AC1024 وغياب HATCH/SOLID وتدقيق ezdxf. تُقارن هندسة JSON المنزّل من WebAssembly مع المحرك المحلي، بما يشمل الغرف والجدران والأثاث والفتحات والدرج وبسطة الوصول والمناور والشرفة والمواقف والخدمات والمساحات، مع سماح عددي ميكرومتر واحد لتنسيق الأعداد.

القيود: هندسة مقترحة، لا رفع مساحي أو موافقة بلدية. الملحق تابع للفيلا ولا يدعم وحدة مستقلة في واجهة التوليد الحالية. مواصفات وحدات التكييف وحساب الأحمال والصوت والتوصيلات والصرف والتفاصيل الإنشائية للملحق والشرفة والدرابزين والإخلاء والهوية العمرانية والكود الكامل لا تُعتمد من هذا النموذج. بيانات القياسات اليدوية تبقى طبقات مراجعة منفصلة، ولا تتحول إلى جدران تنفيذية تلقائيًا.
