# جدوى تشغيل محرك «أنت المهندس» محليًا على أندرويد

هذه تجربة محرك مستقلة عن استوديو الويب، وليست تحويلًا مكتملًا للتطبيق إلى أندرويد. لا نشر لخادم أو موقع، ولا يتغير توزيع المساقط أو الأثاث.

## ما ثبت بالتجربة

شُغّل نفس محرك Python داخل Pyodide/WebAssembly في Web Worker، ثم عُطلت الشبكة في Chromium قبل التوليد. نجح توليد التنظيمات الثلاثة والتحقق منها وتصدير SVG وPDF وDXF 2010 وJSON وتنزيل الملفات. لم تُسجّل طلبات لخدمات خارجية، ولم تُطلب ملفات إضافية أثناء التوليد، واستمر مؤقت الواجهة في العمل أثناء الحساب.

| القياس على جهاز الاختبار المكتبي | النتيجة |
|---|---:|
| تحميل وتهيئة البيئة المحلية | 4.833 ثانية |
| توليد هندسة البدائل الثلاثة | 0.983 ثانية |
| التوليد مع الفحص والتصدير | 9.100 ثوانٍ |
| الحزمة المحلية قبل غلاف Android | نحو 24 ميغابايت |
| كومة ذاكرة WASM الخطية بعد الحساب | 90,439,680 بايت |

قياس الذاكرة يخص كومة WASM فقط؛ ليس إجمالي ذاكرة التطبيق أو WebView. هذه أرقام Linux x86_64 وChromium، وليست أرقام هاتف أو محاكي أندرويد. لكل بديل 24 فحصًا ناجحًا جزئيًا و11 معلقًا وصفر فشل. أعاد قارئ DXF التحقق من AC1024 والوحدات المترية دون أخطاء تدقيق.

طابقت الهندسة الفيزيائية لبديل البهو المترابط النموذج المكتبي تمامًا بعد توحيد تمثيل القوائم واستبعاد معرفات المراجعات. وأعيد فتح DXF المنزّل من WASM وتدقيقه بمكتبة سطح المكتب.

الأدلة في [evidence/browser-offline-result.json](evidence/browser-offline-result.json)، وبصمات الملفات والنسخ في [evidence/bundle-manifest.json](evidence/bundle-manifest.json).

## لماذا WebAssembly للتجربة الأولى؟

الحسابات الهندسية في Python لا تتطلب اتصالًا بخدمة خارجية. لكن التغليف المباشر عبر Chaquopy يحتاج حزمًا أصلية لأندرويد، خصوصًا pydantic-core وPillow وNumPy وpython-bidi. فُحص فهرس Chaquopy ومعلومات PyPI: توفر Pillow وNumPy، بينما لم تتوفر حزمة pydantic-core جاهزة في الفهرس المفحوص. هذا عائق لمسار التغليف المباشر الحالي، وليس برهانًا على استحالة بناء حزمة مخصصة.

Pyodide يوفر pydantic-core وNumPy وPillow مبنية لـWASM. أضيفت بقية المكتبات كعجلات Python خالصة، وحُفظت الملفات والخطوط ومتطلبات المشروع داخل الحزمة. لا نحتاج FastAPI أو Uvicorn في وقت التشغيل؛ مدخل backend/design/offline.py يستدعي المحرك مباشرة.

الإصدارات المستخدمة في التجربة تختلف عن بيئة الويب: Pyodide 0.29.3 وPython 3.13.2 وPydantic 2.12.5 وReportLab 4.4.3 وpython-bidi 0.4.2. لذا لا تُعد التجربة إثباتًا أن ملف requirements.txt الحالي يمكن تثبيته على أندرويد دون تعديل. أُعيد فحص المخرجات الفعلية بهذه المجموعة.

## حزمة APK التجريبية

نجح بناء نسخة debug في [GitHub Actions](https://github.com/raedalqataa-sketch/ANT-ALMOHANDESd/actions/runs/39136607362)، ونُزلت عبر موصل GitHub وفُحص توقيعها ومحتوياتها. [تنزيل الحزمة التي تحوي APK](https://github.com/raedalqataa-sketch/ANT-ALMOHANDESd/actions/runs/39136607362/artifacts/12140250833) يتطلب تسجيل الدخول إلى حساب له صلاحية المستودع الخاص. يحتفظ GitHub بالحزمة حتى 17 نوفمبر 2026، ويمكن إعادة بنائها من المسار اليدوي بعد ذلك.

فك ضغط ZIP وثبت app-debug.apk، ثم افتح «أنت المهندس — اختبار المحرك». اختر «تهيئة المحرك المحلي»، ثم «توليد التنظيمات الثلاثة». هذه نسخة اختبار المحرك وليست الاستوديو الكامل. لم يتم اختبار تثبيتها أو تشغيلها أو منتقي حفظ الملفات على هاتف بعد.

APK بحجم نحو 24 ميغابايت، حد SDK المعلن 24 واستهداف 35. فُحص توقيع APK v2 بنجاح، وثبت وجود المفسر والمكتبات والمحرك والخطوط داخل الحزمة وعدم طلب صلاحية INTERNET. لا تعني هذه الفحوص ضمان أداء الهاتف. تفاصيل البصمة والبناء في [evidence/android-apk.json](evidence/android-apk.json).

## حدود ما تحقق

لم يُختبر التشغيل أو حفظ الملفات أو الأداء على هاتف أندرويد فعلي أو محاكي. لا توجد شهادة توافق لجميع أجهزة أندرويد أو إصدارات WebView. نجاح بناء APK وحده لا يثبت نجاح تشغيله. إعداد الحد الأدنى API 24 يخص غلاف البناء؛ يجب التحقق من إصدار Android System WebView وميزات WebAssembly على الهاتف المستهدف.

التجربة تشمل التوليد والفحص والمعاينة والتصدير. لم يُنقل استوديو المدخلات والسجل واستيراد Excel بالكامل، ولا يوجد اعتماد هندسي تلقائي أو فحص كامل للمتطلبات المعمارية. الملفات في ذاكرة Python الافتراضية مؤقتة؛ زر الحفظ في غلاف Android يستخدم منتقي ملفات النظام ولا يحتاج صلاحية تخزين عامة. يجب التحقق منه على الجهاز.

## إعادة بناء الحزمة المحلية

```bash
python -m mobile_probe.build_bundle
python -m http.server 8010 --bind 127.0.0.1 --directory mobile_probe/build
```

افتح http://localhost:8010، ثم «تهيئة المحرك المحلي» ثم «توليد التنظيمات الثلاثة». خادم الملفات المحلي يعرض الأصول الثابتة فقط؛ لا ينفذ الحسابات. يحتاج **البناء الأول** اتصالًا لتنزيل المترجم والمكتبات؛ بعدها تعمل الحزمة محليًا دون CDN أو PyPI أو خادم حسابات. لا تُضمّن الملفات الكبيرة المولّدة في Git، ويعيد البرنامج تنزيل الإصدارات المحددة ويتحقق من بصمات العجلات.

لاختبار Chromium الآلي اختياريًا بعد تشغيل خادم الملفات: ثبت Playwright وChromium ثم شغّل `python -m mobile_probe.check_browser`. يحظر الفحص أي طلب خارجي، ويعطل الشبكة بعد التهيئة، ويختبر البدائل الثلاثة والمخرجات وتنزيل الملفات واستجابة مؤقت الواجهة.

## غلاف أندرويد التجريبي

المشروع في android/، ويتطلب JDK 21 وGradle 8.9 وAndroid SDK 35. بعد بناء الحزمة:

```bash
cd mobile_probe/android
gradle :app:assembleDebug
```

يمكن فتح المجلد في Android Studio. حدد sdk.dir في local.properties أو استخدم ANDROID_HOME. يعرض WebView ملفات الحزمة عبر WebViewAssetLoader على أصل محلي HTTPS؛ لا تُطلب صلاحية INTERNET ويُحظر اعتراض الطلبات خارج الأصول المحلية. يُوقع APK بمفتاح debug؛ هو نسخة اختبار وليس إصدار متجر.

يوجد مسار بناء يدوي في GitHub Actions باسم **Build offline engine Android probe** لإنتاج حزمة تنزيل خاصة تحوي APK، دون نشر تطبيق أو موقع. حالة البناء المحلية والأدلة تُوثق منفصلة عن اختبار الهاتف.

## الخطوة التالية للتحقق على الهاتف

تثبيت نسخة الاختبار على هاتف المستهدف، وتهيئتها وتوليد البدائل في وضع الطيران بعد إيقاف التطبيق وإعادة فتحه، ثم فحص المعاينة وحفظ PDF وDXF وإعادة فتحهما. تُقاس مدة التشغيل والذاكرة واستهلاك الطاقة الفعلي. بعدها يمكن دمج واجهة الاستوديو الكاملة والتخزين الدائم وإكمال نسخة التطبيق.

مصادر التوافق: [Pyodide](https://pyodide.org/en/stable/)، [Chaquopy](https://chaquo.com/chaquopy/doc/current/android.html)، [فهرس حزم Chaquopy](https://chaquo.com/pypi-13.1/). المكتبات والخطوط الخارجية تبقى خاضعة لتراخيصها الموجودة داخل الحزمة.
