# Logtura — مراقبة أخطاء «أنت المهندس» (تهيئة دون تفعيل إنتاجي)

## البنية التي تم التحقق منها

- النشر المسجل في `web_studio/deployment.json` و`quality_review/adaptive_residential/evidence/publication.json` يعمل على `ant-villa-personal.woollybat9.chatgpt.site`، بإصدار مسجل 27 بتاريخ 2026-10-22. لا يوجد في المستودع ما يثبت أن الموقع ذاته منشور على Vercel.
- واجهة `/client/` والمولّد يعملان بمحرك Python ضمن Web Worker في المتصفح، على استضافة ثابتة. **سجلات Vercel وحدها لا ترى أعطال هذا المحرك**.
- المصدر `vercel-logs` في Logtura يقرأ سجلات وقت التشغيل لأحدث نشر إنتاجي جاهز عبر Vercel API؛ ليس Vercel Log Drain وليس SDK للمتصفح.
- أضفنا `lovable_integration/telemetry.js` كمرسل اختياري ومحدود للأخطاء. **لا يرسل** متطلبات العملاء، عنوان الموقع، أبعاد الأراضي، محتوى الاستثناءات، stack traces أو تفاصيل التصميم. وهو **معطل افتراضيًا**.
- أضفنا `api/telemetry.js` كدالة Node متوافقة مع نشر Vercel مستقبلًا: ترفض جميع الطلبات ما لم تضبط `ANT_MONITORING_ORIGIN`، وتتحقق من المصدر والحقول المسموح بها وتطبع رموز الأعطال المحددة فقط في سجلات وقت التشغيل. لم ننشر هذه الدالة إلى موقع `chatgpt.site`.

## المطلوب للربط الفعلي

1. معرفة مشروع Vercel الإنتاجي الحقيقي (Project ID وTeam ID عند الحاجة) أو اعتماد نقل الاستضافة بعد مراجعة مستقلة؛ لا تنشر نسخة بديلة صامتة.
2. توفير `VERCEL_API_TOKEN` في بيئة تشغيل خاصة بالـ forwarder، وليس في GitHub أو واجهة المستخدم.
3. تحديد استقبال التنبيهات عبر Webhook HTTPS أو Slack، وتوفير أسراره خارج الشفرة.
4. تجهيز مضيف Docker أو Fly لتشغيل Logtura forwarder. **لا يوجد أمر `logtura deploy vercel`**.
5. تطبيق سياسة خصوصية وحد طلبات فعلي على Vercel WAF/البوابة قبل إتاحة endpoint العام.

## أوامر الإعداد على بيئة تشغيل آمنة

يتطلب Logtura إصدار `@logtura/cli` 0.3.6 أو أحدث وNode 22+. من داخل مجلد منفصل للـ forwarder:

```sh
npm install --global @logtura/cli@^0.3.6
logtura --help
logtura providers list --json
logtura init
# ضع VERCEL_API_TOKEN في متغيرات البيئة السرية، ولا تلصقه في الأوامر
logtura connect vercel
# للمشاريع التابعة لفريق: logtura connect vercel --account-id TEAM_ID
logtura sink add webhook alerts
logtura monitor add errors alerts
```

راجع ملف `logtura.yaml` أو `logt.yaml` المولد من إصدار CLI: اختر معرف **المشروع المقصود فقط**، وهيئ وجهة التنبيه بمرجع لمتغير بيئة سري. ثم نفّذ:

```sh
logtura env --check
logtura validate
logtura bundle -o forwarder
```

تتطلب خطوة تشغيل الحزمة مضيف Docker أو نشرها على Fly وتوفير صلاحيات الوصول إلى مشروع Vercel. **التهيئة وحدها ليست دليلًا على وصول السجلات**. لا تحفظ `.env` أو الحزمة ذات الأسرار في Git.

## بيانات التعريف التلقائية وسلامة الخصوصية

حصر متن الحدث في رموز ثابتة لا يمنع منصة الاستضافة من تسجيل بيانات الطلب الشبكي تلقائيًا، مثل وقت الطلب ومساره وUser-Agent وربما عنوان IP. راجع سياسة الخصوصية وفترات الاحتفاظ لدى Vercel ووجهة Logtura قبل التفعيل للمستخدمين الحقيقيين. ينبغي تطبيق rate limit على مستوى الحافة/جدار الحماية، وعدم ربط رموز الأخطاء ببيانات المشروع أو هوية العميل. تجنب إرسال رسالة الاستثناء الأصلية حتى لو بدت تقنية.

`ENGINE_TIMEOUT` يسجل انتهاء مهلة عامل التوليد، ولا يسجل إلغاء المستخدم نفسه؛ وتُسجل أخطاء بدء Worker وإرسال رسائله دون محتواها. أي إنذار حقيقي يستلزم بيئة استقبال منشورة على الأصل نفسه؛ وجود دالة منفصلة في المستودع ليس كافيًا.

## استقبال أعطال المتصفح إذا أصبح الموقع على Vercel

اضبط في بيئة Vercel: `ANT_MONITORING_ORIGIN=https://YOUR_PRODUCTION_DOMAIN`، باستخدام الأصل الفعلي من دون مسار أو شرطة مائلة أخيرة.

بعد اعتماد الخصوصية والحد من الإساءة، أضف في قالب الصفحة المعتمدة **قبل تحميل** `telemetry.js`:

```html
<script>window.__ANT_TELEMETRY_CONFIG__={enabled:true,endpoint:'/api/telemetry'};</script>
```

يجب أن يكون endpoint على **الأصل نفسه**، وليس عنوان Webhook خارجي. لا تضع أسرار Vercel أو Logtura في JavaScript. دون التهيئة تبقى مراقبة المتصفح متوقفة. موقع `chatgpt.site` الحالي لا ينشر دالة `api/telemetry.js` تلقائيًا.

## تحقق التسليم النهائي

- اختبر أن endpoint يرفض طلبًا عند عدم ضبط `ANT_MONITORING_ORIGIN` أو وجود حقل غير مصرح به.
- أرسل رمز عطل تجريبيًا من صفحة تجريبية على أصل Vercel المصرح، وأكد ظهوره في Vercel Runtime Logs.
- تحقق من وصول **الحدث نفسه** إلى وجهة Logtura، ثم اختبر الحدث المطابق وغير المطابق للفلتر، وأخطاء المصدر والمحول والمستقبل.
- لا تعتبر اختبارات Node أو نجاح bundle اختبارًا للنشر أو الوصول الفعلي.

**الحالة الحالية:** كود الالتقاط الآمن وendpoint والاختبارات أُعدّت للمراجعة فقط. الربط الإنتاجي غير مكتمل لعدم إثبات مشروع Vercel مطابق، وغياب بيانات الاعتماد ووجهة التنبيهات وforwarder المنشور.
