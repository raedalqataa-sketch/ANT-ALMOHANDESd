# المحرك العام 0.6 — إضافات معمارية تُنشأ حسب طلب العميل

خيارات الواجهة الجديدة تنشئ منورًا مفتوحًا ونوافذه، وملحقًا علويًا بجلسة ودورة مياه ووصول الدرج، وشرفة بباب منزلق، وساحة خدمات أرضية. تظهر في المعاينات وPDF وDXF 2010، وتخضع للفحص قبل إتاحة الرسم. [تفاصيل النطاق والقيود](../constitution/saudi/README_AR.md#التوليد-المعماري-الاختياري--06). القياسات التنظيمية اليدوية تحفظ أيضًا دون إسقاطها عند استيراد أو إرسال البرنامج.

المساحات المرنة غير المطلوبة تستبعد افتراضيًا. البحث محدود؛ لا يضمن ثلاثة بدائل صالحة لكل قطعة أو اجتماع كل الإضافات في أرض صغيرة. التعليمات التالية توثق المحرك الأساسي الذي توسع في الإصدار الحالي.

# المحرك العام 0.5 — نسخة أولى قابلة للتجربة

الطلب الجديد: يدخل العميل أبعاد أرضه وبرنامجه، ويبحث التطبيق عن L وU ومتدرج، ثم يختار ويصدر رسومات خطية بلا هاتش، وDXF AutoCAD 2010.

## ما ينفذ الآن

- أرض مستطيلة 8–60 م عرضًا و8–80 م عمقًا، دور أو دوران، ارتدادات يحددها العميل، جهة دخول، سمك جدران، عرض ممر وارتفاع دور.
- جدول فراغات متغير: اسم ونوع ودور وعدد وأقل مساحة وأقل ضلع وسعة نوم حتى شخصين للغرفة؛ حتى 30 صفًا و36 فراغًا.
- بحث محدود في أبعاد الأجنحة والكتلة وتوزيع الطلبات، بواسطة beam search. الأشكال مضلعات مختلفة فعلًا، وليست ثلاثة ألوان لنفس المستطيل. لا يثبت البحث الأمثلية ولا اكتمال فضاء الحلول.
- قلب درج في الموضع نفسه بين الدورين، أبواب مرتبطة بالجدران والممرات، نوافذ على الجدران الخارجية، ومكتبة أثاث atelier-1.0 بتفاصيلها الخطية الأصلية.
- فحوص مستقلة تعيد حساب العدد والمساحات والحدود والتداخل واتصال الموزعات والأبواب والنوافذ وسعة الأسرّة. الفشل يحجب الرسم وPDF وDXF، ويترك تقرير التشخيص JSON.
- إذا لم يتسع نمط للبرنامج، يظهر سبب التعذر؛ لا نحذف متطلبات لإظهار ثلاث نتائج وهمية. قد يبقى فائض داخل الكتلة كـ«مساحة مرنة مقترحة» محسوبة ومنفصلة عن البرنامج؛ استعمالها أو تقليلها يحتاج تطويرًا.
- SVG وPDF وDXF من المشهد الهندسي نفسه؛ كل عناصر الرسم غير النصية بلا fill. لا HATCH/SOLID/TRACE أو خطوط عريضة ممتلئة في DXF العام. الجدران حدود مزدوجة بسماكتها بالمتر؛ الطبقات والسمك الطباعي متاحان في CAD. الإصدار AC1024 ووحدة المتر وفحص ezdxf موثق في كل نتيجة.
- اختيار بديل، حفظ/فتح متطلبات JSON، تنزيل ملفات فعلية، تعطيل تنزيل مراجعة قديمة عند تغيير المدخلات، واستعادة آخر النتائج من المتصفح عند بقاء الملفات في CacheStorage.

## ما لا ينفذ آليًا بعد

فصل مجالس الضيوف ومداخلها، الحمامات الداخلية المتصلة بالغرف، العلاقات والخصوصية المطلوبة بالنص، فحص سير جسم الإنسان وأقواس الأبواب الكامل، النظام المحلي، الإنشاء والخدمات والتهوية والسلم التنفيذي. هذه بنود PENDING وليست PASS. الدوران يدعمان بئر درج مطابقًا، لكن لا توجد شهادة مطابقة للسلم. المساقط مسودات مراجعة، لا مخططات تنفيذية.

النص الإضافي محفوظ صراحة في التقرير ومعلق، ولا يدعي المحرك تنفيذ محتواه. لم تعد متطلبات Excel المحفد مفروضة على كل عميل. الاستوديو السابق `/studio/` يبقى دراسة منفصلة.

## الاستفادة من المستودع الذي حدده المستخدم

راجعنا `raedalqataa-sketch/ANT-ALMOHANDES`، فرع main، الالتزام `ecee6eb`:

- `web/dist/program-editor.js` و`architectural-engine.mjs`: عقد برنامج صريح قابل للتحرير بدل افتراض أسرة ثابتة.
- `engine/release-gate.mjs` و`constitution/IMPLEMENTATION_POLICY_AR.md`: هندسة واحدة للعرض والتصدير، وبقاء المسودات والبنود المعلقة صريحة.
- أضفنا محولًا صريحًا `from_reference_program` للأعمدة القديمة. يرفض المداخل/الحمامات الخاصة غير المدعومة بدل تسطيحها دون تنبيه. لم نَدَّعِ تنفيذ كل JSON الدستور.
- أعَدنا استخدام محرك فرش ومشهد وتصدير مستودع التطوير `ANT-ALMOHANDESd`؛ المحرك العام مسار جديد لا يغير برنامج أو سجلات المستخدم السابقة.

## الذكاء الاصطناعي والتكلفة

المحرك المتاح على الموقع **بحث هندسي**، وليس نموذجًا لغويًا متصلًا. يعمل في Python داخل WebAssembly على جهاز الزائر، فلا توجد فاتورة استدلال أو حاجة إلى مفتاح خدمة مدفوعة للتوليد الحالي. تحتاج الاستضافة والتحميل الأول إلى الإنترنت. وجود مصدر مفتوح لا يعني أن خادم الاستدلال السحابي مجاني.

مساعد اختياري عبر Ollama لتحويل النص العربي إلى اقتراح جدول JSON، ثم التحقق البنيوي ومراجعة العميل قبل التطبيق. لا يُسمح للنموذج بكتابة DXF مباشرة أو اعتماد المطابقة. الحالة «غير متصل» ظاهرة في النسخة الساكنة المنشورة؛ **لم يُنزَّل أو يشغَّل نموذج حقيقي في هذه الجلسة**. اختبارات الربط تستخدم ردودًا محاكية، ولا تثبت جودة فهم النموذج.

تحققنا من المصادر الرسمية في 2026-10-18:

- [Ollama: ترخيص MIT](https://github.com/ollama/ollama/blob/main/LICENSE).
- [Qwen2.5-7B-Instruct: أوزان بترخيص Apache 2.0](https://huggingface.co/Qwen/Qwen2.5-7B-Instruct).

لتشغيل المساعد على جهازك أو خادمك بعد تثبيت Ollama:

```bash
ollama pull qwen2.5:7b
OLLAMA_BASE_URL=http://127.0.0.1:11434 OLLAMA_MODEL=qwen2.5:7b uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

افتح `/generate/` على خادم FastAPI. يستطيع المشغّل وضع FastAPI خلف HTTPS وتوجيه موقعه إليه لاحقًا؛ هذه النسخة الساكنة لا تخفي مفتاحًا ولا تفترض وجود خدمة Ollama عامة مجانية. يتحدد استهلاك الذاكرة والسرعة حسب النموذج والتكميم والجهاز. عنوان Ollama يحدد من بيئة الخادم فقط، ولا يقبل عنوانًا عشوائيًا من الزائر.

## البناء والتحقق

```bash
python -m pytest -q
node --check web_generator/app.js
python -m web_studio.build --output /path/to/site/dist/studio
python -m web_generator.build --output /path/to/site/dist/generate
```

`web_studio` يضم حزم Python/runtime نفسها، و`web_generator` يستخدمها عبر Worker مستقل. Native FastAPI ونسخة المتصفح يشتركان في `general_engine.py` والمصدر الهندسي والتصدير. لا يُرفع برنامج العميل أو مساقطه إلى نموذج لغوي عند التوليد على الموقع الحالي.

الوحدات الجديدة والواجهة العامة بترخيص MIT في `ENGINE_LICENSE`. الخطوط والاعتماديات الخارجية تبقى تحت تراخيصها؛ ملفاتها مرفقة بالحزمة الأساسية.
