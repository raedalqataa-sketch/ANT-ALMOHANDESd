# ANT-ALMOHANDES — Development instructions

## Scope and safety
- Work only on the explicitly authorized feature branch. Never modify or merge main or existing Codex branches without explicit approval.
- Inspect relevant files and existing tests before editing. Preserve compatible APIs and existing working components.
- Make small coherent commits; report exact commit IDs and distinguish implementation from verified results.

## Execution
- Use local targeted tests for fast feedback when available. Use GitHub Actions for repository-related integration tests and engineering generation on standard GitHub-hosted ubuntu-latest runners in public repositories only. Never enable paid runners or change billing settings without approval.
- Prefer existing workflows; avoid redundant runs. Keep artifact retention short (one day for synthetic test generation). Never upload private client data to public repositories or artifacts.
- For long searches, implement deterministic batches and resumable checkpoints; do not reduce search coverage or quality solely to meet time limits. Do not claim checkpoint support until tested.
- Inspect actual job logs, artifacts and exit status. A green workflow alone is not proof of a valid design. If access is unavailable, report the blocker.

## Architectural acceptance
- Prioritize applicable safety and regulatory constraints, client program, functional relationships, privacy and usability, then aesthetic preferences.
- For the interlocking-mass engine, establish functional wings, circulation and coordinated vertical cores before allocating rooms; evaluate connectivity, wet-service alignment, openings and room proportions.
- Reject blocking violations rather than offsetting them with high scores elsewhere. Identify checks requiring missing data or specialist review.
- Generate and inspect actual plans from engine geometry; do not substitute illustrative AI images for verified outputs. Keep plan, massing and downstream representations tied to the same revision.
- Report test results, unresolved issues and next concrete step concisely. Never claim professional quality without visual and engineering review.
