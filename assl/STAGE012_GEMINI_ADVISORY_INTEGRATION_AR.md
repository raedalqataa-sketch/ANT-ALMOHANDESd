## ما أُنجز فعليًا

1. `backend/design/ai_lab/providers.py`: قبول `response_schema` الصارم اختياريا في دالة `Provider.propose`. القيمة الافتراضية القديمة `SearchPlan` لم تتغير. يستمر فحص `GEMINI_API_KEY` وإقرار المجانية وعدم تسجيل الأسرار كما كان.
2. `assl/stage012_gemini_bridge.py`: تعريف `Stage012SearchPlan` الذي يسمح بثلاثة إلى ستة اقتراحات فقط، مع **ثلاث فئات بنيوية مميزة على الأقل**. خيارات كل اقتراح محدودة إلى نوع جناح الضيوف، نوع تفرع الحركة، وموضع عقدة الحركة من قوائم مغلقة. لا تُقبل إحداثيات خام، مساحات بديلة أو تبديل اشتراطات.
3. تحويل الاقتراحات إلى الفرضيات التي يتيحها `relationship_first_012.layouts()` فعليا فقط. إذا اقترح Gemini تصميما غير مدعوم أو غير ممكن يذكر التقرير `UNSUPPORTED_OR_INFEASIBLE_SOLVER_LAYOUT`، ولا يستبدله بمحاكاة صامتة.
4. `assl/stage012_feedback_search.py`: إضافة معامل `layout_sequence` لاختيار مجموعة فرضيات المحرك الحقيقي؛ لم تتغير قيود MILP ولا شرط نجاح `stage012_validation_gate` مع مراجع 008/009/010. كما أصلح `reason_codes` لعدم التعطل إذا كان سجل الفحص الأولي null.
5. تحقق مسبق يمنع أي طلب Gemini إن خالف ملخص الأرض 20×25، الاستعمال السعودي، الارتدادات التي تعطي غلاف 15.3×20.3، الفصل بين الضيوف والأسرة، أو هوية/عدد غرف خط الأساس المرجعي 009. إرسال ملخص المعلومات الضرورية فقط، دون أسماء المشروع أو المالك أو العناوين أو الملاحظات.
6. `tests/test_assl_stage012_gemini_bridge.py`: 11 اختبارا مكتوبا لمخطط الاقتراحات، منع الحقن الإحداثي، عدم احتساب النقل البسيط تنوعا، رفض المخططات غير المتاحة، اختبار Gemini `httpx.MockTransport` دون اتصال حقيقي، الخصوصية، انعدام المعاينة الصورية للنجاح، وتطابق البرنامج.
7. `tests/fixtures/stage012_gemini_advice_example.json`: مثال مُصطنع غير صادر عن Gemini لتمكين التجربة دون إنفاق.
8. `.github/workflows/stage012-gemini-advice-offline.yml`: تشغيل **يدوي فقط**، مفاتيح فارغة صراحة، اختبارات مخططات الخيارات وتجربة MILP صغيرة، يرفع التقرير حتى إذا رُفضت الهندسة. لا يعمل آليا حتى تُحل مشكلة ميزانية Actions.

## أوامر التحقق والتشغيل دون إنترنت — بمجرد توفر بيئة المشروع

```bash
python -m pytest -q tests/test_assl_stage012_gemini_bridge.py tests/test_assl_stage012_feedback.py tests/test_ai_lab_providers.py
python -m assl.stage012_gemini_bridge --mode offline \
  --plan-file tests/fixtures/stage012_gemini_advice_example.json \
  --repacks 1 --seconds 1.0 \
  --out stage012-experimental/offline_advice_012.json
```

الخروج بكود `2` **متوقع عند عدم الحصول على ثلاثة بدائل مجتازة فحوص 009/010**؛ يستمر إنشاء تقرير رفض JSON، ولا يعتبر نجاحا وهميا.

## تشغيل Gemini الحي مستقبلا — *فقط بعد التأكد من المجانية وتوفر بيئة موثوقة*

المدخلات الاصطناعية هي بيانات الأرض 20×25 والبرنامج فقط. على الخادم الآمن، وليس المتصفح أو المحادثة، يتوفر `GEMINI_API_KEY`. تحقق مالك الحساب بنفسه من أن المشروع غير مفوتر وأن النموذج مناسب للطبقة المجانية؛ بعدها فقط يمكن ضبط `GEMINI_FREE_TIER_CONFIRMED=true`، والموافقة الصريحة على إرسال البرنامج:

```bash
python -m assl.stage012_gemini_bridge --mode live \
  --model YOUR_CONFIRMED_FREE_GEMINI_MODEL --allow-remote-program \
  --repacks 2 --seconds 1.0 \
  --out stage012-experimental/live_gemini_advice_012.json
```

المعامل `--model` لا يُعَد تأكيدا لتوفره أو مجانيته. عدم إقرار المجانية أو المفتاح الصحيح يمنع الطلب، ولا توجد إعادة توجيه تلقائية إلى محرك آخر أو اعتماد وهمي. تشغيل Live **لم يحدث** في هذه المرحلة.
