# واجهة متطلبات العميل

واجهة عربية RTL من خمس خطوات منشورة على `/client/` بجانب المحرك القائم. تشمل Excel، استعادة مسودة مؤقتة في التبويب لمدة 12 ساعة، مراجعة المجهولات، ثم تشغيل محرك Python الحقيقي داخل iframe من الأصل نفسه. لا حسابات أو بيانات مشاريع وهمية أو API مدفوع. هذه واجهة الإدخال العامة المقتبسة من مصدر Lovable؛ ليست مزامنة لحساباته أو قاعدة بياناته.

## البناء

```sh
npm ci --prefix client_web --ignore-scripts --no-audit --no-fund
npm run build --prefix client_web
python -m client_web.build_site --site /path/to/existing-site
```

يتطلب الأمر الأخير وجود `.openai/hosting.json` وأصول المحرك المعتمدة في `dist/studio`. يتحقق بناء الحزمة من تطابق مصدر المحرك، ويشارك أصول Python والخطوط من `/studio/`، ويضيف رابط الصفحة الرئيسية دون استبدال الواجهات السابقة. ملفات runtime الناتجة وnode_modules مستبعدة من Git.

## التحقق

`quality_review/client_web/browser_qa.py` يختبر المعالج الكامل داخل iframe بصلاحياته الفعلية: Excel تالف وصحيح، حفظ المسودة، عدم طمس القيم، تشغيل Python وإيقافه وإعادته، ثلاثة أنماط، تنزيل الملفات، وحجب التصدير القديم بعد تعديل المتطلبات. ملفات الدليل JSON تسجل نتيجة محلية ولا تعني اعتمادًا تنفيذيًا أو مطابقة شاملة للكود السعودي.

إصلاحان ضروريان للتضمين: مسار `generate/index.html` الصريح، وصلاحية `allow-forms` لإرسال نموذج المحرك. لا يكفي اختبار المحرك في إطار غير مقيد.

## مسار العميل التلقائي

الواجهة الافتراضية الآن ثلاث خطوات بمدخلات الأسرة والأرض فقط. `?mode=advanced` يحافظ على المعالج التفصيلي السابق. التخطيط في `backend/design/architect_planner.py` ويعمل عبر Worker داخل المتصفح أو `/api/v3/auto-design` في خادم Python. لا تُطلب القيم المقترحة من العميل ولا تُخلط بالاشتراطات الرسمية؛ المجهولات محفوظة والمراجعة المحلية معلقة. اختبار الرحلة `quality_review/automatic_architect/browser_qa.py`، وتدقيق الملفات القابل لإعادة الاستخدام `quality_review/generation_round2/audit.py`.
