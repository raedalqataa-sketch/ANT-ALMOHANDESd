# ArchLang وAspicio في ANT-ALMOHANDESd

## ما أُضيف

إعداد `.mcp.json` يتيح أداتين محليتين عبر stdio لعميل تطوير يدعم `mcpServers`:

| الأداة | الحزمة المثبتة مباشرة | الاستخدام |
|---|---|---|
| ArchLang | `@chanmeng666/archlang-mcp@0.2.45` | تأليف وفحص المساقط بلغة ArchLang |
| Aspicio | `@aspicio/mcp@0.13.2` | فحص حقائق DXF وPDF ومعاينتها بحسب أدوات الحزمة |

هذه إضافة لأدوات وكيل التطوير. لا يغيّر هذا التعديل توزيع الغرف أو محرك التوليد أو المصدرات الرسمية أو صفحة العميل، ولا ينشر الموقع. الحزمتان تعلنان MIT في بيانات npm التي فُحصت لهذه الإصدارات. لا يحتاج الإعداد مفتاح API أو اشتراك خدمة؛ استهلاك نموذج الوكيل والاستضافة منفصل. تثبيت النسخ المباشرة لا يقفل التبعيات المتعدية ولا يغني عن مراجعة الترخيص عند إعادة توزيع الحزم.

مصادر الناشرين:
- https://github.com/ChanMeng666/archlang/tree/main/packages/mcp
- https://github.com/frontsail-ai/aspicio/tree/master/packages/mcp

## التفعيل

1. ثبّت Node.js وnpm؛ بيئة التحقق هنا Node.js 24.22.1.
2. افتح المستودع في عميل MCP يدعم إعداد `.mcp.json`، وفعّل الخادمين من إعدادات العميل. إن لم يدعم الملف تلقائيًا، انقل إدخالي `archlang` و`aspicio` إلى إعداد MCP الخاص به حسب توثيقه.
3. يشغّل العميل `npx -y` مع اسم الحزمة ورقمها المثبت. التنزيل الأول يحتاج إنترنت؛ قد تنفذ npm نصوص تثبيت الحزم. لا تُضاف الحزم إلى متطلبات خادم Python أو تطبيق العميل.
4. وجود الملف أو نجاح السكربت لا يثبت أن عميلك حمّله تلقائيًا؛ تأكد من ظهور الأدوات داخل العميل المستهدف.

## فحص دون اتصال

من جذر المستودع:

```bash
python scripts/check_cad_mcp.py
python -m unittest discover -s tests -p test_cad_mcp.py -v
```

لا يستدعي الفحص npm أو أي خادم. يرفض فقد الأداتين، الإصدارات العائمة، تغيير الأمر، وإضافة endpoint أو متغيرات غير متوقعة إلى إعداد الأداتين. يسمح ببقاء أدوات MCP إضافية أخرى دون تشغيلها. الوحدة الجديدة قابلة للجمع أيضًا ضمن pytest الموجود في متطلبات المشروع.

## اختبار اتصال اختياري

```bash
python scripts/smoke_cad_mcp.py --live --timeout 90 --report cad-mcp-connection-new.json
```

يتطلب `--live` صراحة لأنه يشغّل الحزمتين وقد ينزّلهما. يختبر `initialize` ثم `notifications/initialized` و`tools/list` (بما فيه الصفحات)، بمهلة محددة. يغلق العمليات بعد الاختبار؛ على POSIX يغلق مجموعة العمليات أيضًا. لا يستدعي `tools/call`، ولا يقرأ مخططات المستخدم، ولا يرفع ملفات لخدمة بعيدة. قد تنشأ اتصالات تنزيل npm عند التشغيل الأول. التقرير لا يستبدل ملفًا موجودًا؛ اختر اسمًا جديدًا للاحتفاظ بالأدلة. أخطاء الاتصال تعيد exit code غير صفري ولا تتحول إلى نجاح.

## بوابة القبول المعماري التالية

1. حدد نسخة معتمدة من الحالة اليمنية بمسقطين PDF وDXF وبصمات للملفات. نفّذ التجربة على نسخة منفصلة، دون تغيير الأصل.
2. وثّق مخطط هندسة المحرك الحالي وأنشئ محولًا يحفظ معرفات الغرف والجدران والفتحات، الوحدات، المحاور والأدوار. ارفض العناصر غير المدعومة بدل إسقاطها بصمت.
3. قارن حدود الأرض والبناء، عدد الغرف ومساحاتها وأبعادها، الفتحات، اتصال الحركة ومواقع الدرج والمواقف قبل التحويل وبعده.
4. افحص DXF: الترويسة والوحدات والمقياس، أصل الإحداثيات، الطبقات، الكيانات غير المدعومة، الخطوط المكررة، الحدود المغلقة، الأبواب والنوافذ، الأبعاد والنصوص العربية، المنحنيات وتعدد الأدوار.
5. افتح DXF في Aspicio وعارض CAD مستقل وقارنه مع PDF والهندسة الأصلية. وثّق الخصوصية والتهوية ومسار حمام مجلس الرجال وفصل الضيوف والأسرة.
6. أبقِ المخرجات مسودة أو `READY_FOR_REVIEW` حتى اكتمال الفحوص وموافقة صريحة مستقلة. اكتشاف الأدوات أو نجاح فحوصها لا يعتمد المخطط ولا يستبدل قواعد المشروع المحلية.
